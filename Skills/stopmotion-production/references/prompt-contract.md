# 提示词分层与项目绑定

用于从制作要求派生生图／编辑提示词，以及把试片问题反馈到技能。技能保存制作方法；每次调用的成品提示词需要包含当前项目的具体信息。具体不等于过拟合，跨项目误带参数或把局部解法写成普遍规则才是问题。

## 三层边界

| 层 | 保存内容 | 不应承担的内容 |
|---|---|---|
| 通用技能 | 定格替换方法、连续性不变量、约束推导方式、检查标准 | 上次试片的角色名、主题、材质、固定比例、动作顺序、道具或小样清单 |
| 项目规范 | 本项目母版、风格、实体与尺度、世界规则、事实边界、状态表、动作依赖 | 自动成为其他项目的默认值 |
| 本次调用 | 当前项目与镜头／资产、所用版本、参考文件、进入状态、目标姿态、允许变化及输出要求 | 从无关项目补足缺项，或把本次提示词回写成通用技能 |

默认调用提示词只描述技能能力与当前任务入口；不携带某部作品的参数。无项目输入时先建立简报，不能默认继续最近的 demo。跨项目复用某项设计需有当前项目的明确依据。

## 从项目编译到调用

1. 确认 project_id、任务范围及镜头／资产 ID，读取当前有效的母版、几何、状态、动作和输出规范。核对参考图获准复用的范围，风格认可不能替代几何、状态或动作认可。区分已确认值、明确假设和待定值；关键接触或状态前提缺失／冲突时先补设计，暂停受影响的生成。
2. 只选择与当前姿态有关的规则。写清保持项、允许变化、state_in → event／action_phase → state_out；图像只表现其中的目标时刻，不把静帧提示写成同时完成整段动作。
3. 用具体值展开模板，并附工具能实际读取的参考。不可把“保持一致”作为唯一约束，不把未解析占位符交给生图。工具不支持的参数不伪造；必须靠结果检查的约束仍保留验收要求。
4. 保存精确实际调用与来源映射：rule_version、project_id、项目规范版本、shot_id／asset_id、参考版本／路径、尺度／机位／状态／动作引用及其取值。规则改变后新调用引用新版本，不覆写历史提示词。
5. 图像验收与动作播放验收分别记录；提示词包含约束不代表模型已做到。失败时先判断是规则缺失、项目设定冲突、绑定遗漏、工具未遵循还是合成错误，再修改相应层。

可按工具能力调整以下骨架；花括号仅用于编写模板，实际调用前须填充：

```text
任务：生成 {{project_id}} 的 {{asset_id}}，用于 {{shot_id}} 中的定格姿态替换。
依据：{{实际参考文件及其用途}}；{{适用的规范版本与具体取值}}。
表现材质、视角与画布：{{当前项目参数}}。
整画面／完整角色／交互组合与成员：{{当前模式及应包含的实体}}。
保持不变：{{身份、几何及本阶段未变化的可见状态}}。
目标时刻：{{action_phase}}；由 {{state_in}} 经 {{event}} 到达 {{target_state}}。
接触与支撑：{{本阶段资源占用、承托、接触点、遮挡关系}}。
允许变化与禁止漂移：{{本次变化集合及适用的不变量}}。
合成输出：{{透明性、边界、支点、阴影管理等当前要求}}。
```

不适用的字段可删除；无角色的素材不强加角色、操作器官或持物描述。精确标签／数字另外排版。规范若以 ID 引用，需在可见提示正文中展开必要值；不要假设工具可访问项目台账或理解私有 ID。

整画面另读 [阶段母版与整画面替换](full-frame-workflow.md)，指定角色形态、场景几何、阶段状态和前帧各自的参考职责。工具看得到多张图不代表知道冲突优先级；不能用过时母版回滚当前状态。

## 从 demo 问题提炼规则

按“观察到的失败 → 根因与证据 → 可复用不变量及适用条件 → 项目中的具体解法 → 提示词绑定 → 验收办法”处理。不能只把角色名替换成变量，保留同一套道具和动作剧本。

先检验反例：换材质、负载、角色结构、交互方式或无角色过程后，规则是否仍成立？若只能在特定条件下成立，将条件写清或留在项目规范。通用规则约束结果与推导，项目配置决定动作方案。

新增约束前检查是否已有规则覆盖；已有规则未正确绑定或结果未验收时修复执行，不重复堆叠更具体的禁令。带专有名词、数值、私有路径和实际生成记录的复盘留在项目或独立审查报告，不放进可自动加载的通用参考。
